# 收藏页检索与播放器补完设计（第二批）

- 日期：2026-09-16
- 状态：已实施并通过验证（用户确认「开始」后落地）
- 前提：第一批「常驻播放器 + 跨专辑队列」已落地（见 `2026-09-16-collection-player-upgrade-design.md`）
- 范围：收藏页的查找能力（搜索 / 排序）+ 播放器的三处小补完

## 1. 背景

第一批把播放体验做完了：常驻、跨专辑队列、Media Session、现场恢复。现在这页的瓶颈换成了**找到东西**：

| 现状                                      | 问题                           |
| :---------------------------------------- | :----------------------------- |
| 75 张专辑 / 41 位艺术家 / 666 首曲目      | 封面墙只能靠眼睛翻             |
| 艺术家药丸默认只显示 12 个 + 「展开全部」 | 艺术家一多，药丸条本身也要翻   |
| 曲名只存在于 `/collection/data.json`      | 站内搜索（Pagefind）搜不到歌名 |
| 没有任何排序                              | 想按年份或曲目数看一遍做不到   |

播放器侧还剩三处第一批明确划到非目标的缺口：

1. 队列只能被整张专辑**替换**，没法把第二张专辑追加进来（拼不出「这几张一起听」）；
2. 播放失败只有自动跳下一首，没有「重试这一首」；
3. 窄屏下迷你条常驻在底部，会压住正文与页脚的最后一行。

## 2. 结论

### 2.1 收藏页：搜索框 + 排序（纯客户端，零新依赖）

在艺术家药丸下面加一行工具条：一个搜索框（`type="search"`，带自绘的清除按钮）和一个排序下拉，
右侧是原来的「全部播放 / 随机播放全部」，中间夹一个「显示 N / 75 张」的计数。

**匹配范围**：专辑名、艺术家名、**曲名**。命中曲名时，卡片下方最多列两行「含《曲名》」（按专辑内曲序），
点这一行直接播那一首。
搜索框与艺术家药丸是**叠加**关系：药丸选定的艺术家是硬筛选，关键词在结果里再过滤。

**排序选项**：默认（跟随快照的 `alphabeticalByArtist`）、专辑名、艺术家、年份（新→旧，缺年份的排最后）、
曲目数（多→少）。

**数据来源分两层**，这样没网也能用：

| 能力                          | 数据来源                                                                                                                         |
| :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| 专辑名 / 艺术家匹配、五种排序 | 构建期写在卡片上的 `data-*` 属性（`data-album` / `data-name` / `data-artist` / `data-artist-name` / `data-year` / `data-songs`） |
| 曲名匹配、命中曲名后直接播放  | `/collection/data.json`（也就是播放器已经在收藏页预热的那一份）                                                                  |

也就是说：曲库没取到时，搜索与排序照常工作，只是少了曲名这一维；整个功能对没有 JS 的读者退化成今天的样子。

### 2.2 曲库读取收成共享模块

新增浏览器侧模块 `src/utils/musicLibrary.ts`：`loadLibrary()`（带模块级缓存与失败重试）、`peekLibrary()`。
播放器与收藏页的搜索都从这里取，两个消费者共享同一个 Promise —— 收藏页不会为了搜索再拉一份 79 KB。

### 2.3 播放器：专辑卡「加入队列」

收藏页每张专辑卡加一个小按钮（`[data-album-enqueue="<专辑 id>"]`），语义与主按钮区分开：

| 操作             | 行为                                                                         |
| :--------------- | :--------------------------------------------------------------------------- |
| 点封面 / 标题    | 用这张专辑**替换**队列并开始播放（现状不变）                                 |
| 点「＋」         | 把这张专辑**追加**到队列末尾，不打断当前播放；队列里已有的曲目跳过，不留重复 |
| 队列本来就是空的 | 「＋」等同播放这张专辑                                                       |

反馈不依赖播放器面板（面板收起来时看不到状态行）：按钮自身变成 ✓ 并改 title 为「已加入队列」，1.6 秒后复原。

### 2.4 播放器：失败重试

状态行右侧加一个只在出错时出现的「重试」按钮（`#np-retry`）：清掉错误状态、把当前这首从上次的位置重新加载。
自动跳下一首的逻辑保留（连续失败 3 次后不再自动跳）—— 那时「重试」就是唯一出路，`aria` 上也把状态行标成错误。

### 2.5 播放器：窄屏给迷你条让位

迷你条可见时给它一个类（`html.mp-mini-open`），窄屏（`max-width: 40rem`）下 `body` 补一份底部内边距，避免压住页脚最后一行。
只在窄屏加：桌面端面板/迷你条在右下角悬浮，不该改变整页高度。

## 3. 非目标（这批不做）

- 专辑详情页 `/collection/album/<slug>/`（可分享链接 + 曲名进 Pagefind）—— 留到下一批，等这批的检索用一阵子再定。
- 流派 / 年代筛选：只有 30/75 张有流派且中英日混着，得先做归并表才有意义。
- 反代注入 Subsonic 凭据：纯安全项，不产生新功能。
- 播放速度、睡眠定时、真实频谱可视化：YAGNI。

## 4. 关键取舍

| 决定                                         | 理由                                                                            | 被放弃的方案                                                                  |
| :------------------------------------------- | :------------------------------------------------------------------------------ | :---------------------------------------------------------------------------- |
| 搜索/排序主要靠卡片上的 `data-*`             | 无网、曲库未取到也能用；排序不需要把 666 条曲目搬进内存                         | 全部靠 payload 匹配（收藏页会依赖一次 79 KB 请求）                            |
| 收藏页的筛选逻辑单独成 `collectionFilter.ts` | 这页现在是「艺术家 + 关键词 + 排序」三件事，比 `chipFilter` 的通用契约复杂      | 继续用 `chipFilter` 再叠一层（两个 owner 抢 `hidden`，必然互相踩）            |
| 曲库读取收进 `musicLibrary.ts`               | 播放器与搜索共用一个缓存，收藏页不会重复拉取                                    | 各自 fetch 一份                                                               |
| 「加入队列」用卡片上的独立小按钮（兄弟节点） | 卡片主按钮不动结构，改动局限在 CSS + 6 行模板                                   | 把 `<button>` 卡片拆成 `<div>` 包两个按钮（结构、焦点样式、触屏显隐都要重做） |
| 命中曲名的那一行可点播                       | 「搜到歌名」的直接目的就是听它；复用播放器入口，不新增播放逻辑                  | 只标出命中曲名，播放仍需先打开专辑                                            |
| 排序不做「最近添加」                         | 快照里没有加入时间（同步脚本只拉了 `alphabeticalByArtist`），要做先得改同步脚本 | ——                                                                            |

## 6. 验证计划

实施后按这份清单实测，全部通过：

- `npm run lint` / `format:check` / `check:assets` / `check`（0 error）/ `build`（88 页 + Pagefind 索引）全过。
- 无头 Chrome（CDP）34 条断言全过，覆盖上面 8 条 + 边界细节：
  1. 搜「標本」→ 8 / 75 张，清除按钮出现，计数文案正确；搜 `zzzqqq` → 0 张 + 空结果提示；点清除 → 75 张全回来；
  2. 搜 `彼岸花` → 卡片下标出「含《標本Ⅰ：彼岸花》」，点它直接播那一首（面板打开、进度 1/2）；
  3. 排序切「年份」→ 首张是 2026（快照最大年份），缺年份的排最后；
  4. 关键词 8 张 → 叠加艺术家药丸后 7 张，且都在该艺术家名下、药丸高亮；
  5. 拦截 `/collection/data.json` 后：按专辑名仍可搜、排序仍可用、曲名命中行不出现（降级符合预期）；
  6. 「＋」加入第二张专辑 → 队列变长、当前播放曲目不变、按钮显示「已加入队列」；
     重复点 → 队列长度不变、提示「已经在队列里了」；
  7. 拦掉流地址后播放 → 状态行说明原因 + 出现「重试」；恢复网络后点重试 → 错误提示消失、按钮收回、音源重新加载；
  8. 迷你条可见时 `html.mp-mini-open` 生效，400px 宽下 `body` 底部内边距 85.5px。
- 回归：第一批的两轮断言（16 + 16 条）全过；端到端那条确认了「请求已发出、未暂停、站内跳转后元信息与进度都对」，
  音频数据在另一次运行里实测到位（`readyState 4`、进度 2.4s）。首帧时长受 FRP 波动影响（实测 4～14s 都有）。

实测中发现并修掉一个真问题：`play()` 的 reject 回调无条件写「浏览器拦下了自动播放」，
会把音源加载失败的提示（以及随之出现的「重试」）覆盖掉。现在只在 `audio.error` 为空时才这么提示。
