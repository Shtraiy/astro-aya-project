# 播放器与检索的密度收尾（2.2.1）

- 日期：2026-09-17
- 状态：已实施并通过验证（按用户给的 4 张截图逐条处理）
- 前提：2.2.0 的常驻播放器、跨专辑队列、收藏页检索、搜索结果按栏目筛选都已落地
- 范围：手机端播放器面板、收藏页命中曲名那一行、文章底部、搜索结果列表

## 1. 背景

2.2.0 把功能补齐了，用户拿手机和桌面各用了一遍，指出四处「看着别扭」：

| 位置           | 现象                                                                                     |
| :------------- | :--------------------------------------------------------------------------------------- |
| 手机端播放器   | 播放键不在面板中线上；进度条是一条看不出能拖的细线；曲目行偏高；头部文字挤到提前截断     |
| 收藏页搜索命中 | 卡片下方出现正文大小的裸文本（「含《某曲》」），换行后糊成两行                           |
| 文章底部       | 「相关阅读」重复了栏目 / 标签 / 归档 / 搜索已经覆盖的能力                                |
| 搜索结果       | 每条结果 30/40px 的内边距 + 21px 粗标题 + 整宽描边，一屏只装得下三四条；命中词是一块色块 |

## 2. 结论

### 2.1 手机端播放器：先把"错位"修掉，再谈好看

- **播放键回中线**：`.np-ctrl` 原来是「模式按钮靠左、音量靠右、各自 `auto` 外边距」，而音量那一块
  比模式按钮宽，中间三个键就被顶偏了。改成左右两块 `flex: 1 1 0` 各占一半、一个起点对齐一个终点对齐，
  中间自然落在中线上；窄屏把音量条收窄到 3.25rem，320px 级窄机直接隐掉滑块（硬件键调的就是这个音量）。
- **进度条**：轨道从 `--palette-muted`（浅色主题下几乎等于底色）换成 `muted-text 28%`，补一个
  12px 的拖动圆点（`.np-fill::after`，跟着填充宽度的右端走），悬停/聚焦时圆点放大；时长为 0 时不画圆点。
- **曲目行**：窄屏把行内边距压到 0.5rem、"下一首播放"图标收到 1.5rem，行高约 46px → 40px；
  触屏下那个图标从"满色"降到 0.7 透明度 —— 每行都有一个，太抢眼。
- **头部**：外链与收起两个图标收进 `.np-head-actions`（间距 0.125rem），头部 gap 0.75rem → 0.625rem，
  封面窄屏 3.25rem → 2.75rem；标题 / 艺术家因此能多显示两三个字。队列进度「1/10」做成淡底胶囊。
- **状态行**：加载 / 缓冲 / 失败这条提示夹在列表和进度条之间，裸文本像掉出来的一行字，改成淡底提示条。

### 2.2 收藏页命中曲名：一行描边胶囊

「样式丑陋」的根因不是设计，而是 **样式根本没生效**：`.album-hit` 由 `collectionFilter.ts`
`createElement` 出来，拿不到 Astro 的作用域类（`is:global` 之外的选择器会被改写成
`.album-hit:where(.astro-xxxx)`），于是那几个字以正文字号直接铺在卡片下面。

修法：`.album-hits :global(.album-hit)`，并且把它做成**描边胶囊**（强调色描边 + 强调色文字 + 播放小三角），
和「全部播放 / 随机播放全部」那排按钮同一副长相；文案从「含《某曲》」缩短成曲名，超长省略号截断，
完整曲名留在 `title` 属性里。悬停只加深描边 —— 不铺实心强调色底，避免旧浏览器（不支持 color-mix）
下强调色文字落在强调色底上。

### 2.3 删掉「相关阅读」

栏目、标签、归档、搜索四条路都能找到下一篇，文章底部再列三篇同类文章只是重复占位。删掉构建期算分逻辑、
模板与样式（`PostDetails.astro` 少 75 行），底部的收束回到「上下篇 + 版权 + 评论」。

### 2.4 搜索结果：从"卡片"收回"列表"

Pagefind 默认 UI 是给大屏内容站设计的，密度对个人博客太高。收法：

- 结果标题 21px → 1rem / 600；摘要 1rem → 0.8125rem，最多两行（`-webkit-line-clamp`）；
- 每条结果的 30/40px 内边距 → `0.5rem 0.75rem`，去掉上下描边，改为悬停底色 + 圆角；
- 一条结果里的多个命中位置（小标题）再降一级：0.875rem 中性色，悬停才变强调色；
- 命中词从"22% 强调色色块"（连词后面的空格一起变成方块）改成强调色文字 + 细下划线；
- 「共 N 条结果」跟着收紧，「加载更多结果」跟站内胶囊按钮统一，栏目筛选块底部 2px 强调色描边压成 1px；
- 窄屏下筛选栏与结果区之间 60px 的空档压到 1.25rem。

选择器写成 `.search-shell .pagefind-ui .pagefind-ui__results .pagefind-ui__result …` 这种四到五级是有意的：
Pagefind 的默认样式挂着两个 Svelte 作用域类（特异性 0,3,0），层级不够压不住，只能靠层级而不是 `!important`。

## 3. 非目标

- 播放器功能层（队列、Media Session、现场恢复）不动，这批只动样式与头部结构。
- 不做手机端"全屏播放页"（把队列收进二级面板）：改动面太大，先在现有抽屉上把密度调顺。
- 专辑详情页、流派归并表等 2.2.0 已列的非目标，仍然不做。

## 4. 关键取舍

| 决定                               | 理由                                                        | 被放弃的方案                                         |
| :--------------------------------- | :---------------------------------------------------------- | :--------------------------------------------------- |
| 控制行左右两块等宽（flex 1 1 0）   | 不动 DOM、不改 JS，播放键就回到中线                         | 把播放键单独 `position: absolute` 居中（脱离流）     |
| 窄屏删掉音量滑块（≤21rem）         | 320px 级机器上它会把控制行挤变形，而硬件键本来就管这个音量  | 保留滑块并允许控制行溢出                             |
| 命中曲名做成描边胶囊               | 和这页其他胶囊按钮同一副长相；也不依赖 color-mix 兜底       | 强调色淡底胶囊（旧浏览器兜底成实心强调色，字看不见） |
| 命中曲名的文案只留曲名             | 卡片栏宽只有 ~110px，「含《…》」会被截成看不出是什么        | 保留「含《…》」（更明确但几乎全被省略号吃掉）        |
| 删相关阅读而不是删别的             | 它与栏目 / 标签 / 归档 / 搜索四条路径重复，且要算分、要维护 | 保留但缩小成一行链接                                 |
| 搜索结果改悬停底色而不是继续用描边 | 一屏能多放两条结果，视觉噪音也更低                          | 保留描边只压内边距                                   |

## 5. 验证

- `npm run format:check` / `npm run lint` / `npm run check`（0 error）/ `npm run build`（89 页 + Pagefind 索引）全过。
- 无头 Chrome（CDP）实测，dev 与构建产物（`astro preview`）各看一遍，浅色 / 深色、桌面 / 触屏（
  `--blink-settings=primaryHoverType=1,availableHoverTypes=1` 模拟 `hover: none`）都覆盖：
  1. 手机端播放器：播放键落在面板中线上；进度条有圆点；曲目行更密，触屏下"下一首播放"是灰色；
  2. 收藏页搜「彼岸花」：命中行是描边胶囊「▶ 標本Ⅰ：彼…」，`dist` 里 `.album-hits:where(...) .album-hit` 已是不带作用域的子选择器；
  3. 文章页：底部只剩上下篇，`related` 相关标记在模板 / 样式 / 脚本里全部消失；
  4. 搜索页（浅色 / 深色 / 带小标题的结果各一遍）：5 条结果 + 加载更多按钮占的高度，原来只够 3 条半。

## 6. 后续可做

1. 手机端把队列收进二级面板（面板本身只留封面 / 进度 / 控制），现在是"底部抽屉里再滚动一列"。
2. 搜索结果支持键盘上下键在结果间移动。
