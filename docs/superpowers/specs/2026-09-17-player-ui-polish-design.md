# 播放器 UI 精修（2.2.1）

- 日期：2026-09-17
- 状态：已实施并通过验证
- 前提：2.2.0 的常驻播放器、跨专辑队列、收藏页检索都已落地；2.2.1 早前已做过一轮手机端可用性修补
- 范围：`src/components/MusicPlayer.astro`、`src/styles/music-player.css`（播放逻辑、数据结构、入口事件一律不动）

## 1. 背景

按用户给的播放器截图与其列出的十七条要求，对播放器做一次「视觉精修」而不是重设计：
保留深蓝灰底 + 橙色 accent、圆角卡片、紧凑密度与现有交互，只调整层级、留白、颜色权重与状态反馈。

提要求时已经做好、无需再动的部分：播放键最大且用 accent、当前曲目有左侧色条 + 淡底 + 加粗、
已播段用 accent、圆角层级（面板 > 曲目行 > 按钮）、按钮都带 `aria-label`。

## 2. 结论（逐条对应）

### 2.1 层级：三级控件分开

| 层级 | 元素            | 处理                                                                                           |
| :--- | :-------------- | :--------------------------------------------------------------------------------------------- |
| 一级 | 播放 / 暂停     | 保持最大、圆形、accent；落影 `0 6px 18px 42%` → `0 4px 14px 30%`，hover 1.06 → 1.05、按下 0.96 |
| 二级 | 上一首 / 下一首 | 颜色提到「正文色 78%」的灰白（原来和三级控件一样是 muted）                                     |
| 三级 | 随机 / 音量     | 保持 muted；随机选中态底色 14% → 12%，不跟播放键抢眼                                           |

### 2.2 曲目列表

- **序号**：不透明度 0.72，字号与颜色本来就比曲名弱；当前曲目那一格被音浪条 / 播放三角占用，所以序号会换掉。
- **曲名**：`flex: 1 + ellipsis`，长时间保持单行；总时长 `flex: none` 永远贴右。
- **分隔线**：30% → 18% 的中性色，列表读起来是一整条列表，而不是一叠独立卡片。
- **滚动条**（本次最大的一处）：宽 5px、底色透明、滑块平时透明，鼠标移到列表上才以 muted 34% 浮出、直接悬停滑块升到 60%；
  只在 `@media (hover: hover) and (pointer: fine)` 里做，触屏交给系统默认行为。

### 2.3 当前曲目：播放与暂停给出不同提示

播放中保持原有的三根音浪条（纯 CSS 动画，暂停时用 `animation-play-state` 冻住画面）；
暂停时同一格换成一个小 ▶（`.np-tplay`），并给该行 `.np-track-main` 打 `aria-current`。
两个状态只靠 CSS 切换（`.np:not(.is-playing) .np-track.is-current …`），没有新状态变量、没有新依赖。

### 2.4 进度条

- 已播段 accent，未播段 `muted-text 28%`（低对比度灰蓝），轨道悬停提到 45%。
- 拖动圆点 12px → 14px，hover / 聚焦 1.12 倍，`transition 120ms`，不加阴影。
- 时间行左右间距 0.5rem → 0.625rem，给圆点留出不出界的余量；播放中已播时间用 accent。
- 交互（点击跳转 / 拖动）完全没动，只补了 `.np-progress:focus-visible` 的虚线轮廓。

### 2.5 顶部信息与按钮反馈

- 顶部第三行（当前曲名）原来用 accent，和列表里高亮的当前曲目重复强调，改为中性色 —— 信息保留、权重降低。
- 所有图标按钮统一 `:active { scale(0.96) }`（播放键同样 0.96），过渡 120–150ms，不加发光、不加渐变。
- 键盘焦点统一成站内那套「2px 虚线 + accent」：上一首 / 下一首 / 播放 / 收起 / 外链 / 进度条 / 音量 / 迷你条 / 曲目行的「下一首播放」。

### 2.6 音量：不做 hover 展开

要求里写明「如果实现会明显增加复杂度则不要实现」。现有布局在 390px 下已经放得下（左右两块各占一半、
播放键居中），再做 hover 展开要额外一套展开状态与焦点管理，收益有限，故保持现状。

## 3. 关键取舍

| 决定                                        | 理由                                                                                          | 被放弃的方案                                            |
| :------------------------------------------ | :-------------------------------------------------------------------------------------------- | :------------------------------------------------------ |
| 滚动条只在「有真 hover 的指针设备」上自定义 | 触屏滚动条是系统覆盖层，硬接管会破坏原生滚动手感                                              | 全局 `::-webkit-scrollbar`（会波及移动端）              |
| WebKit 与 Firefox 两条路分开写              | Chrome 121+ 见到标准属性就切平台滚动条（约 15px 带箭头），而 Firefox 反过来不认 `::-webkit-*` | 只写标准属性（拿不到 5px）/ 只写 webkit（Firefox 无效） |
| 暂停用 ▶、播放用音浪条（纯 CSS 切换）       | 不引入新状态、不改播放逻辑，又满足「暂停状态要能看出来」                                      | 在 JS 里同步维护一个额外的类                            |
| 顶部当前曲名降成中性色而不是删掉            | 列表滚走时它仍是有用的「在放什么」，只是不该和列表里的高亮重复抢焦点                          | 直接删掉这一行（信息缺失）                              |
| 音量不做 hover 展开                         | 需求明确「复杂度高就别做」，优先稳定                                                          | hover 展开（多一套状态 + 焦点管理）                     |

## 4. 验证

- `npm run format:check` / `lint`（0 error）/ `check`（0 error）/ `build`（89 页 + Pagefind 索引）全过。
- 无头 Chrome（CDP）实测，浅色 / 深色、1280 / 700 / 390 宽三档，鼠标 hover 与触屏 `hover: none` 两套媒体环境：
  1. 滚动条：`offsetWidth - clientWidth = 5`（没还原 `scrollbar-color: auto` 时是 15 且带箭头按钮）；不 hover 时滑块不可见，hover 后以 34% 浮出；
  2. 注入超长曲名后 `row.scrollWidth <= row.clientWidth`，曲名仍是 `text-overflow: ellipsis`，时长依旧贴右；
  3. 暂停时 `.np-tplay` 为 `flex`、`.np-eq` 为 `none`；强制 `.is-playing` 后反过来，且 `#np-cur` 变成 accent；
  4. 当前曲目的 `.np-track-main` 带 `aria-current="true"`；
  5. 键盘 Tab 之后焦点元素 `matches(':focus-visible')` 为真，计算出的 `outline` 是 `dashed 2px rgb(255,107,1)`；
  6. 390px 下底部控制区不溢出（左右两块 `flex: 1 1 0`，播放键仍在面板中线上）。
- 构建产物里 `@media (hover:hover) and (pointer:fine) { @supports selector(::-webkit-scrollbar) { … } }` 结构完整保留。
