# 音乐收藏页升级：常驻播放器与跨专辑队列

- 日期：2026-09-16
- 状态：按用户「按照你的想法进行修改」执行，代码已落地并通过验证
- 范围：`/collection/` 的播放逻辑升级 + 曲库投递方式改造

## 1. 背景

收藏页此前是一个纯静态的封面墙（75 张专辑 / 666 首曲目）加一台**只挂在这一页**的浮空播放窗
（`CollectionPlayer.astro`）。核对代码后，四个缺口按「用户最容易感知」排序是：

1. **离开就断**：`release()` 挂在 `astro:before-swap` 与 `pagehide` 上，点进任何一篇文章，
   音乐立刻停。而组件本身已经为常驻铺好了路（单例 `activePlayer`、文档级只绑一次的点击委托、
   `disconnectedCallback` 收尾），最后又主动把播放停掉。
2. **队列走不出专辑**：状态只有 `albumIndex` + `trackIndex`，`shuffle` 是个布尔值，
   只能在当前专辑内洗牌，也没有「下一首播放」。
3. **手机端没有后台能力**：没接 Media Session，锁屏 / 耳机线控 / 车机都不认这个播放器。
4. **现场不留**：只有音量与随机开关进了 localStorage；刷新或返回后要重新点专辑、从第 0 首开始。

顺带一处工程债：曲库整份内联进收藏页 HTML（157 KB 页面里约 132 KB 是它能曲库），
而页面按钮靠 `data-album-open="<可播放专辑里的下标>"` 与播放器对齐，加一张无曲目专辑就会错位。

## 2. 结论

### 2.1 播放器提到布局层常驻

新增 `src/components/MusicPlayer.astro`（替代并删除 `CollectionPlayer.astro`），在 `Layout.astro`
里渲染，根元素带 `transition:persist="music-player"`。Astro 的 ClientRouter 在换页时会把带这个属性的
**同一个 DOM 节点**搬进新文档，所以 `<audio>`、闭包状态、迷你条全都活着，站内翻页音乐不断。

页面 → 播放器的入口仍然是文档级事件委托，只在初始化时绑一次：

| 入口                       | 作用                                         |
| :------------------------- | :------------------------------------------- |
| `[data-album-open="<id>"]` | 用这张专辑替换队列并开始播放                 |
| `[data-play-all]`          | 全库顺序播放（666 首进队列）                 |
| `[data-play-all-shuffle]`  | 全库随机播放（队列整体洗牌，并切到随机模式） |

### 2.2 曲库改成按需加载的静态 JSON

新增 `src/pages/collection/data.json.ts`（`prerender`），把快照发布成 `/collection/data.json`；
读取逻辑收进 `src/utils/collectionData.ts`，收藏页与端点共用一份。

曲库只点播放时才取（收藏页在 `requestIdleCallback` 里预热），失败可重试，内存里缓存一份。
效果：收藏页 HTML 从 157 KB 降到 90 KB，且首屏不再为「可能不播放」的曲库买单。

### 2.3 队列扁平化，跨专辑

队列从「专辑 + 曲目双索引」改成 `QueueItem[]`（`{albumId, trackId}`，见 `MusicPlayer.astro`）：

- 「全部播放 / 随机播放全部」把全库塞进一条队列，上一首 / 下一首 / 播完自动接都在队列里走；
- 队列跨多张专辑时，面板列表按专辑画分组标题（单专辑保持原来的干净列表）；
- 每行右侧有「下一首播放」，把队列里任意一首挪到当前之后（不产生重复项）。

### 2.4 播放现场与系统集成

- **Media Session**：曲名 / 艺术家 / 专辑 / 封面进系统媒体面板，播放、暂停、上下首、快退快进、
  拖动进度都接管；`setPositionState` 让锁屏进度条动起来。
- **sessionStorage 现场**：队列、当前曲目、进度、播放模式都存下来。刷新或整页进入时恢复，
  但**先不出声**（浏览器不允许无手势自动播放，也不该白下一遍音频），迷你条停在右下角等一次点击。
- **标签页标题**：播放时前缀 `▶ 曲名 · `，跳页后由 `astro:page-load` 重新拼，停止即还原。

## 4. 关键取舍

| 决定                                           | 理由                                                                                          | 被放弃的方案                                           |
| :--------------------------------------------- | :-------------------------------------------------------------------------------------------- | :----------------------------------------------------- |
| 曲库走端点按需取                               | 播放器常驻后，内联曲库等于让每篇文章都背 150 KB                                               | 内联 JSON、或每个页面都预取曲库                        |
| 恢复现场时不出声                               | 浏览器自动播放策略 + 不做无谓的音频下载                                                       | 恢复即 `play()`（大概率被拦截，还白下一遍）            |
| 现场存 sessionStorage                          | 语义是「这次浏览还没听完」，关掉标签页就清干净；也避免下次打开站点突然冒出迷你条              | localStorage（跨会话留下幽灵播放器）                   |
| 点专辑**替换**队列                             | 单队列语义：点了新专辑就该听新专辑，不会出现「怎么还在放上一张」                              | 追加到队列（要额外 UI 才能看到队列里混了什么）         |
| `disconnectedCallback` 延后 800 ms 再收尾      | Astro 换页时会把节点在文档之间搬一次，中途会触发 disconnected；不加延时会在换页瞬间把音乐停掉 | 立即 `release()`（虽然只有老浏览器会踩，但踩了就断播） |
| 曲目行 `content-visibility` + `scrollIntoView` | 全库队列有 666 行，离屏行先不渲染；滚动定位交给浏览器算，避免自己量 offset 受估算高度影响     | 全量渲染 + 手算 scrollTop                              |
| `data-album-open` 传专辑 id                    | 索引一旦和数据不同步就点错专辑                                                                | 传 `playableIds` 下标                                  |

## 5. 风险与兜底

| 风险                                             | 兜底                                                                                 |
| :----------------------------------------------- | :----------------------------------------------------------------------------------- |
| `transition:persist` 在某次 Astro 升级后行为变化 | 元素真离开文档时 `disconnectedCallback` 仍会收尾（不会出现「看不见的播放器还在响」） |
| 曲库端点被搜索引擎收录                           | `astro.config.ts` 的 sitemap filter 排除 `/collection/data.json`                     |
| 播放器常驻后每个页面多一份 HTML / CSS            | 面板默认 `hidden`，样式进共享样式表；实测首页 HTML 28 KB                             |
| 全库队列 666 行渲染卡顿                          | 行很轻（无缩略图）、`content-visibility`、只在队列变化时重建列表                     |
| 恢复现场时曲目已从曲库消失                       | 恢复时按当前曲库过滤队列，过滤后为空就丢弃现场                                       |

## 6. 验证

- `npm run lint`、`npm run check`（0 error）、`npm run build`（88 页 + Pagefind 索引）。
- 构建产物：`dist/collection/data.json` 79 KB；收藏页 HTML 157 KB → 90 KB；
  `dist/index.html` 里 `<music-player>` 带 `data-astro-transition-persist="music-player"`；
  sitemap 只收 `/collection/`。
- 无头 Chrome（CDP）实测两轮共 32 条断言全通过，覆盖：点专辑开面板、站内跳转后**同一个节点**
  且队列与面板保留、整页刷新后迷你条恢复、曲库端点可用、全库队列 666 首 / 75 个分组、
  音源拼装带 `u/t/s`、「下一首播放」跨专辑重排、随机模式、单专辑队列不画分组、页面无 JS 报错。
